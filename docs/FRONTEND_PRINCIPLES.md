# Frontend Principles

## 1. Screen is a composition, not a page

A FATHER screen is assembled from independent modules according to the user's current task.

The same module may appear docked, floating, full-screen, minimized or embedded in another workspace.

## 2. Information is multi-stream

Canonical priorities:
- **Primary** — the user's current task.
- **Secondary** — supporting context.
- **Background** — work happening without demanding attention.
- **Alert** — a condition that requires interruption.
- **Agent** — activity or output from AI/automation specialists.

Visual prominence must reflect semantic priority, not arrival order.

## 3. Attention is a resource

The system may dim, collapse, group or promote modules based on relevance. Motion and glow must communicate state, hierarchy or causality.

## 4. Avatar is independent

ALINA may be full-body 3D, bust, portrait, compact assistant, holographic layer, voice-only or hidden. Identity and state survive presentation changes.

## 5. Visualization is pluggable

Tables, charts, timelines, maps, knowledge graphs, canvases and 3D scenes consume stable data contracts.

## 6. Composition is explicit

A Composition Engine describes active modules, priority, placement and mode. Layout decisions must be inspectable and serializable.

## 7. Cinematic, but usable

Effects require readable content, keyboard navigation, reduced-motion fallback, graceful degradation and performance budgets.

## 8. Built for reuse beyond ALINA

Shared UI, avatar, scene, animation, input and state systems must remain usable by future FATHER products, including games and simulations.
